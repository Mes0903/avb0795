# 控制面板互動與來源清單

## 目的與範圍

這次調整讓來源辨識、重新整理與快捷鍵設定更直覺，並維持模式與邊框各自獨立的使用方式。 既有控制面板標題列、擷取流程、來源 ID 與原生視窗的擁有關係持續沿用

## 來源清單

為了快速辨識來源，清單需要清楚的欄位、類型配色與控制代碼。 每列使用「類型、名稱與 HWND」三欄，加入淡色列分隔線，名稱欄使用剩餘寬度。 長名稱在欄位內裁切，滑鼠停留時顯示完整字面文字

- 視窗類型文字使用粉紅色，顯示器類型使用藍紫色
- 名稱使用目前主題的一般白色文字，HWND 使用綠色十六進位文字
- 停用列使用灰階文字，選取背景持續標示目前來源
- 類型文字和欄位標題提供與顏色並行的辨識方式
- 來源列以灰階表達停用狀態，生命週期說明集中於面板狀態區
- 顯示器的 HWND 欄顯示灰色的 `—`
- 來源名稱中的 `%`、`##` 與 `###` 按字面顯示，互動 ID 由 SourceId 建立

WindowsSourceCatalog 在列舉時將 HWND 轉為顯示字串，經 SourceDescriptor 與 ControllerSourceRow 複製給 UI。 原生控制代碼的操作與生命週期由 Windows 層管理，選取命令仍攜帶 SourceId

## 自動重新整理

為了持續看到新出現的來源，Application 需要定時更新可選清單，並保護使用者已選取的來源。 新增本次執行有效、預設關閉的 checkbox，標示「自動重新整理（5 秒）」

- 勾選後，閒置且選取為空時，每 5 秒列舉一次
- 選取來源、擷取中與清理期間暫停計時，畫面顯示簡短的暫停狀態
- 回到可更新狀態後，重新安排完整的 5 秒間隔
- 手動重新整理沿用既有的閒置使用條件，成功後更新清單並依新的 ID 集合重新核對選取
- 手動更新成功或失敗後，下一次自動嘗試均相隔 5 秒
- 一次 step 最多執行一次自動更新，跨越多個間隔時安排下一個完整間隔
- 列舉失敗時保留原清單，沿用單一 Application notice 呈現錯誤
- 關閉 checkbox 與結束程式時清除更新期限

UI 透過值命令設定偏好，Application 將期限合併至 next_deadline，WindowsSourceCatalog 提供列舉結果。 這次沿用來源 registry 的 generation 與 runtime lease 契約

## 快捷鍵錄製

為了以實際按鍵設定快捷鍵，UI 需要短期錄製狀態與確認步驟。 使用者按下錄製按鈕後，UI 開啟一個 ImGui modal，等待起始按鍵釋放，再收集 Ctrl、Alt、Shift、Meta 與一個主鍵，並顯示候選組合

主鍵範圍沿用 HotkeyChord 的 A-Z、0-9 與 F1-F12。 修飾鍵可省略。 Esc、取消、控制面板失去焦點、session 更換與控制項停用會結束錄製並丟棄候選。 候選由確認按鈕送出 ReplaceHotkey，Application 與全域快捷鍵介面負責註冊和保存

保留目前已確認繫結的獨立顯示。 註冊衝突維持舊設定，notice 顯示衝突原因。 錄製期間的鍵盤導覽由 modal 管理，候選使用主鍵的首次按下事件，長按重複事件維持同一候選

為了讓錄製目前繫結的操作保持一致，WindowsGlobalHotkey 將驗證過的 HotkeyChord 回報 composition root。 main 先呼叫 DesktopHost 的錄製輸入入口，host 在事件當下確認原生控制面板焦點、清理狀態與 UI 錄製狀態，再把值交給 recorder。 錄製接受事件時顯示候選，其餘事件傳送 RestoreActiveReplicaEditable。 原有 OS 繫結持續註冊，失焦後的恢復命令依事件當下的焦點正常派送

## 模式與邊框

為了讓使用者自由組合邊框與輸入模式，Windows adapter 需要分清一次操作的完整回復快照，以及穿透模式長期持有的輸入樣式。 先以隱藏的原生測試視窗重現雙向切換，再依觀察縮小退出穿透時恢復的責任範圍

驗收序列涵蓋兩個方向：

1. 可編輯、無邊框 → 穿透 → 有邊框 → 可編輯
2. 可編輯、有邊框 → 穿透 → 無邊框 → 可編輯

每步驗證模式、邊框、穿透樣式與原生操作結果。 切換模式保留目前邊框，切換邊框保留目前模式。 失敗後仍執行既有回復驗證，Application 保有 RuntimeStateLost 的清理契約

## 關閉與驗證

底部「結束」按鈕移除，標題列關閉繼續傳送 Quit，沿用正常清理順序
